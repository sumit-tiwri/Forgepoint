Core Philosophy   : "We don't just find a startup. We help prove the solution."
Target Users      : Government Departments, Startups, Academic Evaluators,
                    Youth Innovators, Procurement Officers, and System Auditors

--------------------------------------------------------------------------------
1. EXECUTIVE SUMMARY & PROBLEM STATEMENT
--------------------------------------------------------------------------------
Public procurement across Indian municipal corporations and state departments 
frequently excludes agile startups due to:
  - Rigid turnover criteria and multi-year balance sheet requirements.
  - Civil servant risk aversion and fear of post-procurement audit queries.
  - Lack of an objective, empirical sandbox to validate innovative technology 
    before committing taxpayer funds.

FORGEPOINT solves this systemic bottleneck by creating a transparent, 
tamper-evident 12-stage innovation lifecycle. It takes an unstructured government 
problem, uses artificial intelligence to define 15 procurement-ready outcome 
specifications, matches qualified DPIIT startups, supervises a 90-day controlled 
field pilot, records immutable SHA-256 telemetry evidence, conducts peer-reviewed 
human academic scoring, and issues a reusable "Innovation Proof" certificate that 
qualifies the startup for statutory procurement via GeM Startup Runway and GFR 
Rule 194.


--------------------------------------------------------------------------------
2. HOW THE APPLICATION WORKS (12-STAGE LIFECYCLE)
--------------------------------------------------------------------------------

STAGE 1: PROBLEM DISCOVERY & CHALLENGE REPOSITORY
  - Department officers browse active challenges across municipal solid waste,
    water leakage detection, intelligent traffic corridors, healthcare, and forestry.
  - Challenges are categorized by domain, district, estimated budget, and deadline.

STAGE 2: AI CHALLENGE BUILDER (OUTCOME-DRIVEN SPECIFICATION)
  - An authorized officer enters unstructured text describing operational pain points.
  - The AI engine (Gemini 3.8 Flash with deterministic fallback) automatically
    synthesizes 15 standardized procurement parameters:
      1. Formal Challenge Title
      2. Problem Description
      3. Department & Division
      4. Technical Domain
      5. Core Objectives
      6. Required Technology Stack
      7. Expected Operational Outcomes
      8. Field Constraints
      9. Recommended Pilot Duration
     10. Suggested Baseline vs Target KPIs
     11. Weighted Evaluation Criteria
     12. Required Startup Capabilities
     13. Data Requirements
     14. Cybersecurity & Sovereignty Safeguards
     15. Risk Factors & Operational Mitigations
  - Human officers retain full editorial control before publishing.

STAGE 3: SEMANTIC STARTUP MATCHING ENGINE
  - Compares challenge parameters with candidate startup profiles using explainable
    semantic scoring (e.g., EcoRoute AI: 94% Match, SmartFleet: 88% Match).
  - Explicitly states matching rationale (e.g., heuristics, GIS routing, AIS-140 GPS
    telematics compatibility, prior logistics track record).
  - Mandatory disclaimer: AI score is an assistive shortlisting aid and does not 
    constitute a statutory procurement award.

STAGE 4: STATUTORY ELIGIBILITY SCREENING
  - Objective verification of mandatory compliance requirements:
    * DPIIT Startup Recognition Number
    * GST & PAN verification
    * Proprietary IP ownership and source-code rights
    * AIS-140 automotive GPS hardware compatibility
    * ISO 27001 data sovereignty compliance
    * Non-conflict of interest declaration
  - System status transitions to: "Eligible for Evaluation".

STAGE 5: INDEPENDENT HUMAN EXPERT EVALUATION
  - Academic chairmen (e.g., IIT Delhi) and Smart Cities Mission observers score the 
    candidate startup across 7 criteria on a 1-10 scale:
    * Technical Feasibility & Algorithm Robustness
    * Innovation & Differentiator
    * Scalability Across Municipal Corporations
    * Cybersecurity & Data Sovereignty
    * Cost Effectiveness & Payback ROI
    * Pilot Readiness & Hardware Compatibility
    * Domain Fit & Sanitation Worker Usability
  - Clear architectural distinction between Algorithmic Recommendation (94%) 
    and Authorized Human Peer Score (8.9/10).

STAGE 6: CONTROLLED PILOT CONTROL CENTER
  - Active 90-day sandbox cohort tracking (featured: 40 municipal compactor 
    vehicles in Central Zone, Day 60 of 90).
  - 6 sequential milestones with verifiable deliverables:
    1. Pilot Setup & Protocol Sign-off (Days 1-15)
    2. Telemetry & Sensor Integration (Days 16-30)
    3. Initial Routing Deployment (Days 31-45)
    4. Mid-Pilot Review & Baseline Audit (Days 46-60)
    5. Final Outcome Measurement (Days 61-75)
    6. Independent Panel Validation (Days 76-90)
  - Active field risk register with live mitigations and day-advancement simulator.

STAGE 7: KPI OUTCOME ENGINE & TELEMETRY CONVERGENCE
  - Continuously compares baseline metrics against target and measured telemetry:
    * Daily Fleet Distance : 820 km/day (Baseline: 1,000 | Target: 850) -> 18.0% Drop
    * Diesel Fuel Volume   : 261.8 L/day (Baseline: 320 | Target: 262)   -> 18.2% Drop
    * Clearance SLA        : 94.6% (Baseline: 74.2% | Target: 95.0%)    -> 20.4% Lift
    * Unit Cost per Ton    : Rs 1,130/ton (Baseline: Rs 1,450)          -> 22.1% Savings
  - Displays environmental decarbonization (152 kg CO2e/day) and 3-year projected 
    civic savings (Rs 1.85 Crore).

STAGE 8: CRYPTOGRAPHIC EVIDENCE DOCKETS
  - Chronological repository of raw GPS dumps, fuel vendor audits, and field reports.
  - Every document is stamped with an immutable SHA-256 cryptographic hash to 
    prevent post-hoc tampering during public accounts committee audits.
  - Includes a simulated evidence upload modal allowing operators to calculate hashes 
    and append new dockets in real time.

STAGE 9: INDEPENDENT VALIDATION CENTER
  - Multi-signatory attestation panel requiring digital signatures from:
    * Academic Chairman (IIT Delhi)
    * Mission Observer (Smart Cities Mission, MoHUA)
    * Municipal Superintending Engineer
  - Official Validation Docket Number: GSN-VAL-2026-MH-001.

STAGE 10: PROCUREMENT PATHWAY READINESS REVIEW
  - Validates all 6 pre-conditions and evaluates statutory entry points:
    1. GeM Startup Runway (Exemption from prior turnover and experience under DPIIT)
    2. GFR Rule 194 (Follow-on Commercial Procurement for Proven Solutions)
    3. QCBS 80:20 Swiss Challenge / Limited Competitive Procurement
  - Official statutory safeguard: "Ready for Applicable Procurement Pathway Review. 
    Does NOT bypass statutory procurement rules."

STAGE 11: REUSABLE INNOVATION PROOF REGISTRY
  - Official Certificate: GSN-PILOT-2026-001 with embedded QR verification code,
    complete audited KPI table, and SHA-256 ledger digest.
  - One-click "Print Official Dossier" button formatting the document for physical 
    tendering committees. Eliminates redundant pilot testing across sister departments.

STAGE 12: SCALE DECISION & EXPANSION WORKFLOW
  - Committee decision options: Scale to Additional Departments, Proceed to 
    Procurement Review, Continue Pilot, or Improve Solution.
  - Structured multi-tier replication pipeline:
    * Zone Pilot : 40 Vehicles (Central Zone)
    * City-wide  : 420 Vehicles (All 5 Wards)
    * Regional   : 680 Vehicles (Pimpri-Chinchwad & Chhatrapati Sambhajinagar)
    * National   : 3,500+ Vehicles across 18 Smart Cities

YOUTH INNOVATION HUB
  - Open GovTech challenge board for engineering students, researchers, and developers.
  - Allows developers to submit code repositories and live demos.
  - Awards verified platform portfolio badges and mentor attestations.

SYSTEM AUDIT TRAIL & GOVERNANCE LEDGER
  - Immutable activity log recording timestamp, actor name, user role, action code, 
    target entity, network node IP, and full audit details.
  - Includes search, role filters, and one-click CSV export.

5-ROLE SWITCHER (RBAC)
  - Instant role switching in header to test the platform from different perspectives:
    * Government Officer (Department Lead)
    * Startup Innovator (EcoRoute AI)
    * Academic Expert (IIT Delhi)
    * Youth Contributor (Student / Developer)
    * System Administrator (Auditor)

GUIDED DEMO TOUR
  - 12-step guided demo bar with Next/Previous navigation and contextual descriptions 
    designed specifically for hackathon presentations and jury reviews.

3. TOOLS, TECHNOLOGIES & LIBRARIES USED TO BUILD
--------------------------------------------------------------------------------

A. FRONTEND ARCHITECTURE
  - React 19 (v19.0.1)
    Modern functional component architecture, hooks (useState, useEffect, 
    useContext, useMemo), and StrictMode compliance.
  - TypeScript (v7.0.2 / ES2022)
    Strict type-safety across all domain entities (Challenges, Startups, Pilots, 
    KPIs, Evidence, Evaluations, Audit Logs).
  - Vite (v8.3.0)
    Lightning-fast dev server and optimized production bundler with tree-shaking 
    and ES module support.
  - Tailwind CSS (v4.3.3) & @tailwindcss/vite
    Next-generation utility-first CSS engine using native CSS variables, dark-mode 
    slate surfaces, and responsive bento grid layouts.
  - Lucide React (v0.546.0)
    Crisp, consistent SVG icon set for navigation, status indicators, and domain visuals.
  - Motion / Framer Motion (v12.23.24)
    Fluid micro-interactions, modal transitions, and banner animations.

B. BACKEND & API ARCHITECTURE
  - Node.js (v18 / v20 / v22 LTS support)
    Runtime environment for full-stack execution.
  - Express.js (v4.21.2)
    Lightweight HTTP server mounted on Port 3000. In development, it integrates 
    Vite middleware; in production, it serves static bundles from /dist.
  - tsx (v4.21.0)
    Direct TypeScript execution engine allowing `tsx server.ts` without manual 
    transpilation steps.
  - Dotenv (v17.2.3)
    Loads environment variables securely from .env files.

C. ARTIFICIAL INTELLIGENCE & LLM ENGINE
  - @google/genai (v2.4.0)
    Official Google GenAI SDK integrating Google's Gemini 3.8 Flash model 
    (gemini-3.8-flash) on server-side proxy routes (/api/ai/generate-challenge).
  - Structured Output Parsing
    JSON-mode extraction enforcing 15 procurement-grade parameters.
  - Deterministic Innovation Engine (Offline Fallback)
    Ensures 100% demo uptime and continuous resilience even if offline or 
    without an active API key.

D. CRYPTOGRAPHY, SECURITY & GOVERNANCE
  - Web Crypto API (SHA-256)
    Client-side and server-side cryptographic hashing generating immutable digests 
    for telemetry logs and Innovation Proof certificates.
  - Role-Based Access Control (RBAC)
    Custom context-driven permission boundaries (GOVERNMENT, STARTUP, EXPERT, 
    YOUTH, ADMIN).
  - Human-in-the-Loop Safeguards
    Architectural guarantee preventing autonomous AI tender awards or unverified 
    statutory procurement decisions.

E. CI/CD & DEPLOYMENT TOOLS
  - GitHub Actions (.github/workflows/deploy.yml)
    Automated workflow that installs dependencies, compiles Vite, and publishes 
    static artifacts directly to GitHub Pages on every push.
  - Google Cloud Run
    Containerized production hosting environment serving the Node.js/Express server.


--------------------------------------------------------------------------------
4. HOW TO RUN LOCALLY
--------------------------------------------------------------------------------

1. PREREQUISITES
   - Node.js 18+ or 20+ (Check with: `node -v`)
   - npm 9+ or 10+ (Check with: `npm -v`)

2. INSTALLATION
   cd <project-folder>
   npm install

3. RUNNING IN DEVELOPMENT
   Option A (Full-Stack Mode - Node/Express + Vite):
     npm run dev
     Open: http://localhost:3000

   Option B (Client-Only Fast Mode):
     npm run dev:client
     Open: http://localhost:5173

4. PRODUCTION BUILD
   npm run build
   npm start
   Open: http://localhost:3000
